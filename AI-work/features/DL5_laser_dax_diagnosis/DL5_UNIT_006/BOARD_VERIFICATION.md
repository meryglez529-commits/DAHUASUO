# DL5_UNIT_006：板级 ILA 定位结果（2026-08-05）

## 结论摘要

本次使用同一份诊断 bit/LTX 完成了写侧整行、DAC 读侧/相机同步、采集时序三组 ILA 抓取。

1. 外部激光输入正常：相邻上升沿为 250 个 `eth_clk` 采样，即约 2 us；每个沿都被 State 14 接收。
2. 在重新下发 16x16 测试配置后，`x_index` 从 0 到 15 连续推进，State 16 恰好执行 16 次；本次没有 FPGA 写侧丢失像素。
3. 行尾的窄尖峰已在 DAC 数字码流中定位：倒数第二个 X 像素 `0xD8BD` 保持 2 us，而最后一个 X 像素 `0xE664` 只保持 80 ns，随后立刻开始单调回扫。示波器所见“最后台阶后的窄上冲”正是这个未被保持到下一 laser 的第 16 点，不是模拟链路凭空产生。
4. 行首恢复的 DAC 输出不是由 State 2 写入持续 FIFO word 保证的。回扫返回 `0x1999` 后，下一次可见的 X 增量在约 6.74 us 后出现；这与 State 2 在激光模式仅写两个锚点、随后不持续写 FIFO 的既有 RTL 行为一致，是恢复时间不稳定的直接证据。
5. `camera_line_sync` 在 DAC ILA 的 81.92 us 窗口内始终为高，即使 FIFO bit33 行尾标记已两次出现；低有效相机行同步当前不符合需求。该问题已记录，尚未改 RTL。

### 写侧整行

- 行首触发位于样本 0，`x_index=0`。
- State 15 在每个激光沿后保持 100 个 8 ns 采样，State 16 从 `+0.808 us` 开始；配置的 800 ns 扫描延时生效。
- `x_index=0..15` 连续，16 次 State 16，每次写 4 个 word；没有 `prog_full` 停顿。
- 在 `+30.848 us` 进入 State 12；随后 State 12 共 50 次、State 13 共 100 次，完成 1 us 回扫的 50 个节拍。

### DAC 行尾和恢复

DAC ILA 以 bit33 行尾标记触发（位置 3072）。相对触发时刻，倒数第二个有效点 `0xD8BD` 在两个连续行中均保持 100 个 DAC 时钟（2 us）；最后有效点 `0xE664` 从 `-0.020 us` 保持至 `+0.040 us`，只有 4 个 DAC 时钟（80 ns）。`+0.060 us` 即开始回扫，至 `+1.240 us` 到达 `0x1999`。其后 FIFO 为空/间歇读，直到 `+7.980 us` 才出现下一有效 X 点 `0x2740`。

因此，本次的“回扫末端到下一 X 增量”约为 6.74 us，而非被寄存器严格定义的 5 us；DAC 代码在此区间保持起始值。这个现象与 `parameter_dacdata_gen` State 2 的激光模式实现相符：计数恢复时间但只写两个起始锚点，无法以 FIFO 数据契约保证 DAC 输出恢复时长。

最后点只有 80 ns 的直接原因是 State 16 为每个点仅写 `dac_sample=4` 个 FIFO word；当 `x_index=15` 时，State 4 不再等待下一 laser，而是立即转 State 12 回扫。行内点在 State 14 等下一 laser，因而其 DAC 码值会在 FIFO 排空后继续保持约一个 laser 周期；最后点没有这段等待，故表现为窄尖峰。

### 采集时序

采集 ILA 在样本 512 触发。`laser_pulse_ui` 后，延时状态为 4 个 `ui_clk`（20 ns），采集高电平状态也为 4 个 `ui_clk`（20 ns）。`0x0209=1`、`0x020A=1` 的实际行为正确。

### 相机同步

DAC ILA 中 `camera_line_sync` 的 4096 个 50 MHz 样本均为高；同时 `para_config_dout[33]` 有两次行尾标记上升。这说明问题发生在相机同步的 DAC 域状态机/模式判定路径，不是板外 TRIGGER_H 接线问题。当前 probe 集没有直接记录 `laser_mode_en_dac` 和 FIFO bit34；修复该问题时应把这两个内部量加入后续验证，避免仅凭外部波形判断。
