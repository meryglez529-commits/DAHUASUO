# DL5_UNIT_007：激光模式物理回扫后恢复计时

## 已确认需求

- 激光模式下，配置 `dacx_recovery_time = T` 后，必须在 DAX 实际输出最后一个回扫字之后，再等待不少于 `T`；在此之前不得接受下一行的第一个 laser 上升沿。
- 普通与超快模式的波形、FIFO[32] 的 `adc_tri` 含义、状态机路径和外部接口必须保持不变。
- 不修改 DAC FIFO 的宽度、深度、阈值或 IP；不新增寄存器和引脚。
- 仍以 `dacx_recovery_time` 的微秒配置为准。ETH 写侧计数换算为 `T * 125` 个 `eth_clk` 周期。

## 设计边界

- 当前 State 2 是 `eth_clk` 写侧状态，不是 DAC 引脚状态；其可与读侧回扫重叠。
- FIFO[32] 在激光模式已经固定为 0，且激光 ADC 触发来自独立的 `acq_pulse_ui`，因此仅在激光模式复用 FIFO[32] 作为末回扫字标记。
- 首行没有前一行物理回扫：仍执行配置的恢复等待，但不等待不存在的尾部确认。
- `dax_fall_time = 0` 时也没有尾部回扫确认：同样直接执行恢复等待。

## 验收

1. 激光模式：末回扫 DAC 字更新时产生一次 DAC 域确认；随后至少 `T * 125` 个 ETH 周期后才可进入 State 14 接受 laser。
2. 激光模式：在等待确认及恢复计时期间到达的 laser 不改变 `laser_toggle`、不启动 State 15/16。
3. 普通与超快模式：FIFO[32] 仍分别等于原始 `adc_tri`，不产生尾部确认 toggle，原 State 2 路径不变。
4. 仿真、综合/实现满足项目时序、资源和 DRC 门槛；ILA 可同时观察标记、DAC 确认、ETH 同步值和恢复状态。
