# DL5 激光模式与相机同步示波器测试计划

## 结论与边界

2026-08-04 的 ILA 实测已经确认：J9/D15 的 `laser_sync_in`、CDC、`laser_pulse_ui_1` 与内部 `adc_tri` 均正常。此前未触发的原因是 ILA 布防后没有重新执行“停扫 -> 写 DL5 参数 -> 使能 -> 启动扫描”的完整上位机流程，不是输入信号故障。

历史上“示波器没有看到 blanker，随后 ILA/重新配置后又恢复”的现象没有留下能唯一归因的故障证据；因此不能宣称发现或修复了 blanker RTL/输入故障。本计划将 blanker 仍作为示波器直接验收项，将 DAC 输出作为扫描延迟和驻点的主验收项，并以 ILA 只验证不可直接引出的采集时序。

`TRIG_BLANK` 是低有效 blanker 输出；`TRIGGER_OUT` 是高有效的激光事件 busy 指示。内部 `adc_tri/acq_en` 没有物理 IO，因此“采集数据延时/时间”不能在当前硬件上仅用示波器直接测量，须以 ILA 为验收手段，或另行批准临时调试输出复用。

## 接线与仪器设置

| 通道 | 板卡接口 | 信号 | 用途 |
|---|---|---|---|
| CH1 | J9 SMA, `TRIGGER_IN` | 外部 laser sync 输入 | 基准触发；高有效，3.3 V CMOS |
| CH2 | J19 MMCX, `TRIG_BLANK` | blanker | 低有效输出 |
| CH3 | J22 SMA, `TRIGGER_OUT` | laser event busy | 高有效事件窗口，不是 ADC trigger |
| CH4 | DAC X 模拟输出 | DAX 坐标变化 | 测量扫描延时和实际像素驻点 |

- 使用 CH1 上升沿触发；优先 10x 高阻探头。若信号源和示波器均为 50 Ohm 端接，确认信号源幅度设置后 FPGA 输入仍不超过 3.3 V。
- 每次修改参数后，都执行：停止扫描 -> 写全部 DL5 参数 -> `laser_mode_en=1` -> 启动扫描。仅改一个字段后直接开始不作为验收操作。
- 先保存一张四通道基线图，并记录 bitstream、上位机参数、激光器频率/占空比、示波器时基和探头倍率。

## 第一阶段：激光模式

### 0. 输入与像素节拍基线

1. 激光源接 CH1/J9，设置 3.3 V CMOS 方波。若目标“驻点时间”为 1.000 us，源周期必须设置为 1.000 us（1 MHz）；当前已验证的 500 kHz 输入会得到约 2.000 us 的像素节拍。
2. 运行完整激光启动流程。
3. 验收：CH1 周期、占空比、幅度正确；CH4 相邻像素坐标更新的间隔与 CH1 周期一致。激光模式下外部激光周期才是有效驻点，不以普通扫描模式的 `dac_sample` 单独决定。

### 1. 扫描延迟时间（界面 8 ns，步进 8 ns）

1. 固定其他参数，记录 CH1 上升沿到 CH4 DAC X 新像素台阶开始的时间 `Tscan`。
2. 将扫描延迟从 8 ns 改为 80 ns，重复测量。
3. 验收：两次 `Tscan` 的差值为约 +72 ns；绝对延迟含 CDC、FIFO 与 DAC 时钟量化，不以 8 ns 的绝对值判定。

### 2. 束闸延迟/工作时间（5 ns 步进）

1. 设置束闸延迟 5 ns、束闸工作时间 500 ns。
2. CH1 上升沿为基准，测 CH2 首次拉低的相对时间 `Tblank`，以及 CH2 低电平宽度 `Wblank`。
3. 验收：`Wblank = 500 ns`（允许一个 UI 时钟量化误差）；CH2 为低有效。
4. 灵敏度复测：束闸延迟改为 100 ns，预期 `Tblank` 相对增加约 95 ns；束闸工作时间改为 1 us，预期 `Wblank` 增加约 500 ns。

### 3. 激光事件 busy 窗口

1. 同时观察 CH1 与 CH3。
2. 验收：每个有效激光事件 CH3 都出现高电平窗口；其位置/持续时间可用于确认事件链路连续，但不得将 CH3 当作 ADC 采集脉冲。

### 4. 采集数据延时/时间（界面 20 ns，步进 20 ns）

1. 当前物理接口没有 `adc_tri` 输出，使用已验证 ILA：`adc_tri_r1` 与 `acq_en`。
2. 验收：以 `laser_pulse_ui_1` 为基准，`acq_en` 相对延时符合采集延时，窗口宽度符合采集时间；参数扫描用差分判据，例如延时增加 20 ns 时窗口起点相应后移约 20 ns。
3. 当前 project host-app 对 laser `acq_time` 强制最小 2 个 20 ns 步进，即最小 40 ns；若必须验收界面的 20 ns，需先确认现有上位机是否允许写入原始值 1，或批准调整该安全限制。
4. 若必须在示波器上直观看到实际采集窗，需要单独批准一个临时 debug mux，把 `adc_tri` 或 `acq_en` 复用到空闲物理输出；不能把 `TRIGGER_OUT` 误作采集窗。

## 第二阶段：相机行同步

在第一阶段全部通过后再测试，避免把激光问题与相机同步问题混在一起。

| 通道 | 接口 | 预期 |
|---|---|---|
| CH1 | J20 MMCX, `TRIG_H` | 新增相机行同步，低有效 |
| CH2 | DAC X 或有效像素相关参考 | 行有效区参考 |
| CH3 | J9 laser sync（仅激光模式）或 `TRIG_BLANK` | 行/激光关联参考 |

1. 普通模式：一行有效像素期间 `TRIG_H` 为低，行外为高；逐行重复。
2. 超快模式：同样只覆盖有效像素区，确认行间空隙恢复高电平。
3. 激光模式：从该行第一有效激光像素开始拉低，到最后有效激光像素结束后的一个 DAC 时钟释放为高；行间的激光空档不得把 `TRIG_H` 提前释放。
4. 每种模式都改变 `row_repeat`，验收每一次物理 X 扫描均产生一个独立低有效行窗口。
